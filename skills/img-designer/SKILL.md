# 生图

**没有验收过的图，不算生成完成。** 本 skill 覆盖全流程，模板是其中「构图」一步的资源。

> **根方法论**：`references/photographic-craft.md`——把意思翻译成光学事实（光/影/材质/光学/色彩/文字），以及验收的检查依据（其 §11）。写提示词前读它，验收时按它过。

```
需求 → 拍摄单 → 参考集 → 构图（模板） → 生图/改图 → 验收 ─┐
                          ↑                                │ 不过
                          └──── 重找参考 ←── 定点修 ←──────┘
                                             │ 通过
                                             ▼ 交付卡
```

## 1 接需求 → 拍摄单

先写成表，缺一项就回去问，不许猜：

| 字段 | 例 |
|---|---|
| 主体/产品 | 月亮灯（附实物图） |
| 场景与时间 | 卧室床头、夜 |
| 光源 | 产品自发光，窗外冷补 |
| 画幅与用途 | 3:4 竖版，详情页 |
| 必须出现 | 刻字 `August 02, 1986` |
| 禁止出现 | 玻璃杯、第二光源、道具堆叠 |
| 验收标准 | 可判定项，不写"高级感" |

**事实先查**：日期→月相/节气、历史陈设、产品结构，先给数字和来源再落笔。例：1986-08-02 = 残月 12%、月龄 26、北半球左侧亮。

**冲突先摊**：当"好看"与"事实"打架（胖月牙阴影 vs 真实细月牙），停下问用户，不替客户决定。

## 2 找参考 → 参考集

四类，每张写明"看它什么"：

- **产品实物图**：保真的唯一可靠来源，优先当 `edit_image` 的 source
- **场景参考**：同房型、同家具关系的实拍
- **光线参考**：同光位、同色温
- **风格参考**：配色、质感、年代

**修复轮也要重找**：缺陷涉及材质、光线、结构时，先找一张"正确状态"的参考再改图，不要凭描述硬改。

## 3 构图 → 选模板

模板在 `templates/`，**选中才读**，不要一次全读。

| 主干 shot | 用途 |
|---|---|
| shot-product-hero | 白底主图、抠图、贴版 |
| shot-in-use-scene | 产品在真实空间里的样子 |
| shot-detail-macro | 材质、工艺、刻字 |
| shot-orthographic-3view | 建模、量产、三视图 |
| shot-character-turnaround | 人物转面、服装一致性 |

| 修饰 light | 用途 |
|---|---|
| light-practical-lamp | 自发光产品（夜灯、灯箱） |
| light-softbox | 均匀无影（白底、三视图） |
| light-window-45 | 自然窗光（场景） |
| light-rim | 轮廓分离（深色产品） |

`_negative` 是所有任务都要拼的全局负向；`_schema` 是写新模板时的字段说明。

**拼装**：1 个主干 + 0–2 个修饰 + 负向**只挑 5–8 条**（塞太多模型会丢约束）。

**冲突矩阵**

| 组合 | 判定 | 原因 |
|---|---|---|
| 三视图 × 浅景深 | ✗ | 正交投影不能有焦外 |
| 三视图 × 实用光源 | ✗ | 要均匀光 |
| 人物转面 × 特写 | ✗ | 转面必须全身 |
| 场景 × 白底 | ✗ | 互相抵消 |
| 夜灯 × 高调曝光 | ✗ | 夜景要高对比、保黑 |
| 微距 × 35mm | ✗ | 微距应 ≥85mm |

**填槽纪律**：slots 必须填满；主干 40–120 词、修饰 25–60 词；不复读整段，只换槽位值与风格变体；每张图至少换一个修饰，否则一批图撞脸。

**骨架不是成稿**：模板给的是骨架，按 `references/photographic-craft.md` §3–§7 补齐光的五决策、影的三要素、材质、光学与色彩，最终提示词通常在 150–250 词。

## 4 生图 / 改图

| 情形 | 用什么 |
|---|---|
| 有实物图、要保产品 | `edit_image`，实物当 source |
| 无参考、纯生成 | `generate_image` |
| 迭代上一轮产出 | `edit_image` + **显式 `source_attachment_id`**（默认会吃最新人类消息的图） |
| 只改 1–2 处 | `edit_image`，prompt 只写"改哪里、改成什么、其余不变" |

出图后**必须验实际尺寸与比例**——参数不一定生效（两次请求 3:4 都出成 4:3 是真实案例）。

## 5 验收

先看图：`read_image` 或读会话里的附件。**没看过图不算验收**；文件存在、尺寸正确、sha 都对，都不算。

然后先跑工艺检查（`references/photographic-craft.md` §11）：光的五个决策、影的三要素与接触影、材质按对光反应、最锐点、主色是否绑物体、文字规则、提示词里有没有未换算的形容词、产品状态是否与输入一致。工艺项不过，先改工艺，不要改构图。

### 5.1 硬检查（逐项 PASS/FAIL，写证据）

| # | 项 | 判据 |
|---|---|---|
| A | 需求符合 | 与拍摄单逐条对得上 |
| B | 构图 | 主体完整、留白够、重心合理 |
| C | 文字 | 拼写正确、无乱码伪字 |
| D | 结构 | 无多余部件、无错误融合 |
| E | 物理 | 光向一致、有接触影、反射合理 |
| F | 质感 | 无塑料感、糊、重复纹理 |
| G | 一致性 | 与实物/参考/同批一致 |
| H | 可用 | 分辨率、格式、无违规内容 |

### 5.2 常识（最容易翻车，单独过）

- 家具关系能住人：柜贴墙、床在旁边而不是背后
- 比例可信：产品 vs 桌面 vs 家具
- 光源有来路，影子跟着光走
- 道具小、暗、不反光；透明大件会抢主体
- 反射里能看到真实环境

### 5.3 美感

- 主次：一眼看到的是产品
- 构图：边缘不切主体，留白给版式
- 色彩：冷暖有依据，不脏不灰
- 层次：前景/主体/背景分得开

### 5.4 AI 味与同质化

- 奶油虚化、光斑团、HDR 光晕、过锐
- 塑料感、蜡感、完美对称、影棚摆拍
- 文字伪影、重复平铺纹理
- 与上一张撞光位、撞构图

**判定**：A–H 任一项 FAIL，或常识任一项 FAIL → 不交付。只有美感/AI 味不足时可有条件通过，但必须写明风险。

## 6 循环

- 每轮只修 **1–2 条能具名**的缺陷；说不清"哪里不对"就先写清楚，再开新一轮
- 只用 `edit_image` 修，不整体重生成；结构性崩坏（黑边、错位）→ **回滚上一版**
- 最多 2 轮；仍不过就交付并写明未解决项，不假装合格
- 版本账本：`版本 / sha / 改了什么 / 判定 / 回滚点`——这次靠它救回 v5、丢掉 v6
- 事实冲突（生日 vs 审美）→ 停下问用户

## 7 交付卡

```
结论：通过 / 有条件通过 / 未通过
已检查：A✅ B✅ C❌（右下角文字乱码）
修复：第 1 轮改文字 → 复检通过
未解决：无
```
